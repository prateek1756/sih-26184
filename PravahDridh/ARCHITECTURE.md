# PravahDridh — System Architecture Specification
> **Smart India Hackathon · Problem Statement 26184**  
> **Platform**: Heuristic Engine for Risk Mapping and Early-warning of Suspicious activity

---

## 1. Executive Architecture Summary

PravahDridh is designed as a mission-critical, high-availability, geospatial decision-support platform for **Law Enforcement Agencies (LEAs)**, State Cyber Cells, and Financial Intelligence Units (FIUs). 

The platform addresses the critical challenge of cybercrime cash-outs: perpetrators laundering stolen funds via mule bank accounts and withdrawing liquid cash at physical automated teller machines (ATMs). 

### Core Architectural Principles
1. **Separation of Concerns**: Multi-tiered decoupling across Presentation, Gateway, Analytical Engines, and Authoritative Data Persistence.
2. **Zero Temporal Leakage**: Enforced mathematical boundary ($t < T$) across feature calculation pipelines, guaranteeing that future events never leak into historical inference vectors.
3. **Hybrid Inference (ML + Domain Heuristics)**: Statistical probabilities generated by machine learning models are combined with deterministic expert rules (R01–R06) and temporal decay.
4. **Spatial Optimization**: PostGIS native spatial types (`GEOMETRY(Point, 4326)`) and GIST indexing allow sub-second geographic radius filtering, neighbor counts, and DBSCAN spatial clustering.
5. **Chain-of-Custody & Auditability**: Every state transition, alert acknowledgment, and investigation note is cryptographically stamped with SHA-256 state hashes.

## 3. Detailed Component Decomposition

### 3.1 Client Application Tier (`frontend/`)
- **Technology**: React 18, TypeScript, Vite 6, Leaflet / React-Leaflet, Recharts, Lucide Icons.
- **Role-Based Portals**:
  - **Threat Analyst Portal**: Interactive PostGIS hotspot map rendering ATM clusters, candidate risk scores, and SHAP feature importance charts.
  - **Field Officer Portal**: Prioritized alert feeds, nearest ATM routing, dispatch acknowledgment, and quick-incident status updates.
  - **Supervisor & Commander Portal**: Force allocation heatmap, audit trail explorer, investigator workload management, and model version promotion.
- **Network Resilience**: Axios client configured with automatic JWT refresh interceptor, unified envelope parsing, and network retry logic.

### 3.2 API Gateway & Security Layer (`backend/app/api/`)
- **Framework**: FastAPI 0.111+ leveraging asynchronous event loops (asyncpg / asyncio).
- **Contract Enforcement**: Request and response bodies validated using Pydantic v2 schemas with `extra='forbid'` to prevent injection payloads.
- **Standardized Response Envelope**:
  ```json
  {
    "status": "success",
    "data": { ... },
    "meta": { "page": 1, "per_page": 20, "total": 100, "total_pages": 5 },
    "error": null
  }
  ```
- **Authentication & RBAC**:
  - Stateless JSON Web Tokens (JWT) signed using HS256/RS256 with 60-minute access validity and 7-day refresh tokens.
  - Granular RBAC dependencies (`require_role(...)`) enforcing permissions at route decorators.

### 3.3 Machine Learning Inference Engine (`backend/app/ml/`)
- **Feature Builder (`feature_builder.py`)**:
  - Acts as the single source of truth for both offline historical training and real-time inference.
  - Enforces temporal cutoffs: for any target evaluation at timestamp $T$, only events strictly satisfying $\text{timestamp} < T$ are ingested into the feature vector.
- **Model Architecture**:
  - **Primary Model**: Scikit-Learn `RandomForestClassifier` parameterized with `class_weight='balanced_subsample'` to handle severe class imbalance (~6% positive cash-out rate).
  - **Alternative Evaluated Baselines**: XGBoost and LightGBM with tree-based SHAP explainability.
- **Model Artifact Registry (`backend/artifacts/`)**:
  - `rf-v1.0.joblib`: Serialized production pipeline.
  - `feature_schema.json`: Strict schema containing all 15 feature names in exact matrix order.
  - `metrics.json` & `model_metadata.json`: Transparent auditing of validation PR-AUC, Precision@K, and training hyper-parameters.

### 3.4 Risk Intelligence Engine (`backend/app/services/risk_engine.py`)
- Evaluates domain-specific heuristic rules (R01–R06) based on real-world Indian cyber fraud patterns:
  - **R01 (Velocity Spike)**: $>5$ transactions from same account cluster in 24 hours ($+0.25$).
  - **R02 (High-Value Transfer)**: Single transfer amount $\ge ₹50,000$ ($+0.15$).
  - **R03 (Mule Account Association)**: Mule account detected in transaction chain ($+0.30$).
  - **R04 (Historical Hotspot Proximity)**: $\ge 3$ incidents within 500m radius in past 30 days ($+0.20$).
  - **R05 (Modus Operandi Match)**: Category and time pattern match confirmed cash-out campaigns ($+0.10$).
  - **R06 (High-Risk Time Window)**: Late night (22:00–04:00) or weekend operational window ($+0.10$).
- **Composite Risk Formulation**:
  $$\text{Final Score} = 0.60 \times P(\text{ML}) + 0.30 \times \text{RuleScore}_{\text{norm}} + 0.10 \times e^{-0.05 \times \Delta t_{\text{days}}}$$
- **Severity Mapping**:
  - `CRITICAL`: $\ge 0.75$ (Immediate interdiction dispatch)
  - `HIGH`: $0.55 - 0.74$ (Targeted physical surveillance)
  - `MEDIUM`: $0.30 - 0.54$ (Elevated log monitoring)
  - `LOW`: $0.00 - 0.29$ (Routine state)

### 3.5 Geospatial Engine (`backend/app/services/geospatial_service.py`)
- **PostGIS Native Spatials**:
  - Uses `GEOMETRY(Point, 4326)` for ATM and incident locations.
  - Spatial indexing via PostgreSQL Generalized Search Tree (**GIST**).
- **DBSCAN Clustering**:
  - Executes spatial clustering using the Haversine metric on radian-converted coordinates.
  - Default parameters: $\epsilon = 1.0\text{ km}$, $\text{min\_samples} = 3$.
- **Hotspot Polygon Synthesis**:
  - Computes approximate circular polygon buffers with 24 geodesic vertices around high-risk centers to produce valid GeoJSON polygons for frontend map rendering.

### 3.6 Cryptographic Audit Service (`backend/app/services/audit_service.py`)
- **Forensic Chain-of-Custody**:
  - Implements state hashing across all operational actions:
    $$\text{Hash} = \text{SHA-256}(\text{actor\_id} \mathbin{\Vert} \text{event\_type} \mathbin{\Vert} \text{resource\_type} \mathbin{\Vert} \text{resource\_id} \mathbin{\Vert} \text{timestamp} \mathbin{\Vert} \text{JSON}(\text{payload}))$$
  - Every alert acknowledgment, investigation status update, and model promotion is stored immutably in the `audit_events` table.

## 5. Security & RBAC Architecture

### Role-Based Access Matrix

| Feature / Resource Domain | Public | Viewer | Analyst | Investigator | Supervisor | Admin | ML Engineer |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| User Registration / Login | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| View Heatmaps & Public ATMs | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Ingest Complaints & Transactions | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ | ❌ |
| Run Prediction Pipelines | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ |
| Acknowledge / Resolve Alerts | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ | ❌ |
| Assign Alerts to Officers | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
| Manage Case Investigations | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ | ❌ |
| View Cryptographic Audit Log | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
| Promote / Retrain ML Models | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ |

### Security Controls
1. **PII Masking**: Financial account identifiers and citizen victim names are stored strictly as SHA-256 hashed digests (`source_account_hash`, `destination_account_hash`).
2. **Password Security**: Passwords hashed using bcrypt with salt rounds $\ge 12$.
3. **Session Revocation**: JWT token jti tracking via Redis blacklist allows immediate revocation of compromised credentials.
